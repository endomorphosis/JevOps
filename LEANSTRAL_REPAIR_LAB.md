# Independent proposals versus online compiler feedback

`jevops.leanstral_repair_lab` compares two bounded policies on the same frozen
Arena problem. It first checks the unchanged reference on **every required Lean
pin** using the existing rootless Docker verifier. A failed control stops the
experiment before tokenization or model inference. There is no host-execution
fallback, environment repair, cache deletion, watcher restart, or training.

An optional `--study json-schema --seed 223` runs a different, fresh comparison:
three unconstrained requests versus three requests with an explicit bounded
llama.cpp JSON schema. The default remains `--study repair --seed 211`.
Both schema-study arms receive identical prompts at matching steps, the same
strict `request_id` + tactic-body contract, and the same budgets. Neither sees
prior attempts or feedback. Only treatment requests add `response_format`;
the option is saved before inference and bound into the client receipt hash.
Policy blocks are shuffled, not interleaved: this tiny public development
screen cannot establish causal superiority or held-out performance.

The adapter accepts only the closed schema generated by
`leanstral.tactic_response_format`: required nonce and nonempty tactic string,
no extra fields. Token/response limits and the unchanged host parser enforce
the size bounds; the server schema intentionally omits a large `maxLength`
because this local server rejects its expanded repetition grammar.
Arbitrary schemas and schema/tool combinations are refused;
other router providers cannot silently drop the option. The
[llama.cpp grammar documentation](https://github.com/ggml-org/llama.cpp/blob/master/grammars/README.md)
describes JSON-schema-constrained decoding, but supports only a subset of
schema features. The prompt must still describe the output contract. HTTP 200
does **not** prove that this server/template enforced the requested grammar.
All responses still face the unchanged parser, intake, and every pinned native
proof check. JSON structure cannot establish correct Lean, preserve a theorem,
or prevent an outer `by` inside the tactic string. No old output is salvaged.

The default uses container UID/GID 65534. An explicitly selected
[`--mount-owner-user` profile](ARENA_MOUNT_OWNER_PROFILE.md) provides a separately
identified rootless UID-0 option for owner-only FUSE imports. It is never enabled
automatically and requires fresh isolation and reference controls.
The explicit `--memory-gib 4` or `--memory-gib 8` pilot option changes only the worker memory cap;
its default remains 2 GiB and it never updates the watcher configuration.

## What differs

- **Independent:** three proposals, each seeing the reference but no previous
  output or diagnostic.
- **Compiler feedback:** three proposals; after a native rejection, the next
  sees its own immediately preceding source and source-bound compiler errors.
  Valid or malformed responses clear this repair history. This is not an
  incumbent-refinement or cross-problem memory experiment.

Initial prompts, output contract, sampling temperature (1.0), and token/check
ceilings match. Policy-chain order is seeded and randomized per case. This
compares policies, not temperature settings. It is a small screening experiment,
not evidence of a general improvement from a single problem.

Each policy reserves at most three generations, 6,144 prompt tokens and 1,024
output tokens per request, and 21,504 total model tokens per problem. There are
at most three candidate checks **per pin per policy**, plus one reference check
per pin. Reservations commit before calls; unknown or interrupted work remains
charged. Unspent tokens are not redistributed. Actual usage is reported
separately: equal ceilings do not imply equal consumption.

The server's non-generating `/apply-template` and `/tokenize` endpoints quote
prompt cost, including conservative special-token overhead. See the
[llama.cpp server API](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md).
Missing quotes, missing usage, usage beyond the reservation, or changed visible
server metadata stop the experiment. These checks do not attest model weights
or prove that a server's self-reported token usage is honest.

## Evidence boundaries

Responses must satisfy the existing strict request-bound JSON contract. No
wrapper stripping, JSON salvage, generated tool execution, or intake bypass is
allowed. Only typed, request/source/target-bound receipts can earn validity;
type and axiom policy must also pass. Infrastructure failures stay unknown,
never become proof-rejection feedback, and stop further generation.
Router failures retain bounded error categories and HTTP status codes when
available, but never arbitrary exception text. Older receipts without those
fields remain unknown; their cause must not be guessed from elapsed time.

The ledger retains exact inputs, reservations, raw outputs, usage, and native
receipts. Reports are generated programmatically. Each run is single-use: no
automatic retry, resume, or overwrite. Implementation hashes and file inventory
are checked during execution. The CLI puts compiler scratch under the guarded
run directory, takes the shared build lock, and retains existing storage caps
and caches. A busy shared lock yields `LOCK_BUSY` and exit code 2 without
compiler/model calls or creating a run directory. Incomplete native experiments
also return exit code 2; completed experiments return 0.

All-pin validity and verified source length are screening outcomes. Native
heartbeat observations are retained, but a shorter accepted source is **not**
a heartbeat win; that requires the existing controlled replay benchmark. No
official score, policy promotion, autoencoder training, or held-out quality
claim is produced. Injected test backends are labeled `offline_fixture`.

## Running

Use a fresh output directory inside the existing capped volume. The CLI accepts
only explicitly configured development cases; it does not mine blind canaries.
`Core.InitsUpdatesComm` has already been inspected and is not a fresh holdout.

```bash
# Preview: no model or compiler requests.
python -m jevops.leanstral_repair_lab --watcher-config /path/to/config.json \
  --output /existing/capped/volume/new-repair-run --problem Core.InitsUpdatesComm

# Same command plus --run performs the bounded experiment.
python -m pytest --test-seal=off tests/test_leanstral_repair_lab.py
```

The Python interface permits explicitly separated development and confirmation
records, rejecting overlapping names and exact statement/source content. It
does not infer semantic independence or automatically nominate a policy.

## Schema pilot interruption (2026-09-24 audit)

The six-request schema comparison was implemented and tested, but did not reach
model inference. The live run stopped when its implementation guard detected a
workspace change during reference controls. Its ledger contains two native
reservations: one recorded `VERIFIED` reference and one **unknown** result.
There were zero model reservations. No prompt-quality, token-compression, or
heartbeat comparison is established, and these controls must not be carried
forward as if they belonged to a new run.

The [programmatically generated ledger audit](papers/completion/lean_refactor_arena/evidence/leanstral-schema-interruption-2026-09-24.json)
retains artifact hashes and source drift observed afterward. Audit-time drift
does not prove when each file changed. The original plan, ledger and partial
case receipt are untouched. The watcher is unchanged; no training, promotion,
cache deletion or automatic rerun occurred. The pre-pilot regression suite had
534 passes and 93 skips; the separate live isolation run passed all nine checks.
The follow-up audit/schema fixtures passed 24 tests. All pytest runs disabled
test seals.

For another interrupted run, generate a separate audit without reconstructing
missing native receipts or overwriting the runner's report:

```bash
python papers/completion/lean_refactor_arena/tools/audit_repair_lab.py \
  --run-directory /existing/run --source /repo/jevops \
  --output /new/audit.json
```

The next live comparison needs a fresh run and a frozen source snapshot (see
`jevops.arena_snapshot`), or coordination to keep the workspace unchanged.
Do not disable the mutation guard to complete a comparison.

## Frozen follow-up and grammar-limit diagnosis (2026-09-24)

The [generated follow-up receipt](papers/completion/lean_refactor_arena/evidence/leanstral-frozen-schema-pilot-2026-09-24.json)
records a fresh, read-only snapshot of 388 files (8,131,053 bytes), preserved
unchanged through the run. All 254 frozen-copy regression tests and nine live
isolation canaries passed. The first offline test launch had a missing temporary
parent directory; its 124 setup errors remain in a separate XML report. The
same suite was rerun with a fresh temporary directory, without changing code.

The reference passed on all three pins. Its single-control heartbeats were
4,227 (4.29.1), 4,657 (4.27.0), and 4,689 (4.26.0); these are not refactor gains.

| Arm | Requests reserved | Measured responses | Strict format | All-pin valid refactors |
| --- | ---: | ---: | ---: | ---: |
| Ordinary JSON prompting | 3 | 3 | 2 | 0 |
| Schema requested | 1 | 0 | Unknown | Unknown |

Only one ordinary response reached native checking; all three pins rejected
its generated layout (`unexpected token 'exists'; expected command`). Another
contained a theorem declaration and was rejected at intake, and the third
failed the response contract. No output was repaired, rescored, or trained on.

The first schema request returned HTTP 400. The local server journal contains
that request's nonce, the expanded `char{1,16384}` grammar, and the diagnostic
`number of repetitions exceeds sane defaults`. This is a concrete grammar
construction failure, not evidence of a model context limit. The pilot stopped
with four model reservations and six native checks. Two model slots were left
unused. Known observed model usage is 4,886 tokens; failed-request usage and
the complete total remain unknown. The comparison is incomplete.

The subsequent source patch removes `maxLength: 16384` from the **server
schema only**. The nonempty string requirement, strict request ID, field set,
completion cap, HTTP response cap, 16,384-byte host tactic limit, and all native
proof gates remain intact. Regression coverage also rejects oversized Unicode
strings by byte count. The patch passed 195 regression tests, but was **not**
live-validated in that run and does not change its result. The separate
corrected-schema pilot below tests the patch with fresh requests.

The watcher was unchanged. No training, promotion, cache deletion, storage-cap
increase, or official score occurred. The 50,000,000,000-byte guard passed.

For future runs, `tools/prepare_frozen_schema_pilot.py` prepares an exclusive
snapshot/configuration bundle inside the existing capped volume and emits
`LOCK_BUSY` without creating it if another run holds the shared lock. It starts
neither models nor a watcher. Execute the existing canary/repair tools from that
snapshot with Python `-I -B` and its root explicitly on `sys.path`; do not invoke
the mutable checkout's module. Verify the externally retained snapshot digest
before and after execution. `tools/report_frozen_schema_pilot.py` generates the
compact receipt, retaining setup errors and unknown usage without rescoring.

## Completed corrected-schema pilot (2026-09-24)

The [generated corrected-schema receipt](papers/completion/lean_refactor_arena/evidence/leanstral-corrected-schema-pilot-2026-09-24.json)
records the fresh `leanstral-schema-frozen-20260924-b` bundle, seed 227, and an
unchanged read-only snapshot of 390 files. All 277 regression tests and nine
live isolation checks passed. All three pinned reference controls passed before
inference. This run completed six model requests and 12 native checks; it is
separate from both earlier interrupted/incomplete pilots.

| Arm | Measured responses | Strict format | Reached native checking | All-pin valid refactors |
| --- | ---: | ---: | ---: | ---: |
| Ordinary JSON prompting | 3 | 1 | 1 | 0 |
| Corrected schema requested | 3 | 3 | 2 | 0 |

All three corrected schema requests completed without HTTP errors. This is
live evidence that the grammar-construction blocker was removed for these
requests, not attestation of every server-side schema constraint or a general
prompt-policy win. The sample is one public development problem, three requests
per arm, in policy blocks rather than interleaved trials.

The ordinary failures were an outer `by` wrapper, a truncated response, and a
native rejection. The schema arm produced one embedded theorem declaration
(rejected at intake) and two native rejections. All three candidates that
reached Lean failed on every pin with unsolved goals and
`unexpected token 'exists'; expected command`.

The decoded JSON bodies already had inconsistent top-level indentation:
`intros Hup Hinit` began at column zero, while the following `exists` and `have`
lines began with two spaces. The strict parser preserved those bodies exactly;
they were not damaged by trimming, repaired afterward, or rescored. This
identifies tactic-body/layout instructions as a concrete next experiment, not
a reason to relax the output contract or award correctness for valid JSON.

Reported model usage was 5,423 tokens for the ordinary arm and 4,988 for the
schema arm (10,411 total), against equal reservations of 6,801 per arm. These
are generation costs, **not proof-token reductions**. There was no verified
token or heartbeat improvement, no training, and no promotion. The watcher
remained unchanged; all caches were retained and the 50 GB storage guard passed.
