## Execution and acceptance

The JSON manifest is the machine-readable goal/task graph. The .todo.md is the actual ipfs_accelerate_py task source. Only deterministic producers and protected validators may create execution evidence. Grok4.7 is advisory through the existing llm_router; Leanstral drafts are untrusted until fresh pinned Lean verification.

The first15tasks are the executable bootstrap. The remaining23 are a comprehensive, explicitly planned research backlog; they are not already implemented or silently activated. Each planned ticket must acquire its exact reviewed producer argv, protected native validator and resource/input receipts before becoming pending. The owner can make CPU/Grok progress while these capabilities are absent.

Proof optimization and executable-definition refactoring are distinct. Keep the theorem statement/import/prefix/axiom contract fixed. Any changed executable definition requires a separately proved equivalence/refinement obligation and caller/runtime checks.

Length-first is primary. Keep strict-dual and official multiobjective/Pareto results separately named; never mislabel a shorter-but-slower candidate as improving both. Preserve verified incumbents and the original fallback.

No automatic training, model promotion, competition submission or Git push is enabled by this startup. Explicit benchmark/compute eligibility and release steps remain separate.
