# Proof-carrying neurosymbolic graph cellular automaton

This note describes the implemented runtime in `jevops/proof_ca.py`, not a
proposal for a future subsystem. The offline executable example is:

```bash
python -m jevops.proof_ca_demo
```

The example uses a mock verifier explicitly marked as a fixture. It does not
invoke Lean, a hosted model, an API, a GPU, or a distributed worker.

## State and trust boundary

`ProofGraphCA` receives a finite atom universe, predicate arities, ground Horn
rules, trusted assumptions, targets, an injected policy, and an optional
verifier adapter. A `Cell` contains four independent records:

| Record | Meaning | Authority |
| --- | --- | --- |
| `SymbolicState` | Atom/rule identity, explicit obligation and target identity, complete dependencies, accepted derivation IDs | Checked transition only |
| `PolicyState` | Activation, latent features, uncertainty, observations, rich Jev answer metadata | Never establishes facts |
| `EvidenceState` | References to typed evidence records | References are checked before admission |
| `RuntimeState` | Cell version, execution status, message count, resource reference | Operational bookkeeping |

The accepted fact set is separate from all observations. The only
authoritative evidence kinds are `TRUSTED_ASSUMPTION`, `RULE_DERIVATION`, and
verified `EXTERNAL_VERIFICATION`. Counterexamples, test observations,
inconclusive outcomes, errors, timeouts, cache hits, and legacy `theorem_ok`
fields do not admit facts.

The local policy receives a `LocalSnapshot`, not the runtime. The snapshot
contains cell and edge types, complete mandatory premise IDs, a bounded
neighbor summary, an enabled rule observation, and a dependency fingerprint.
`JevPolicyAdapter` validates allowed choices, finite probabilities, confidence
range, and full answer metadata. `DeterministicPolicy` is the offline
fallback, explicitly identified as a fixture.

`checked_apply` is the admission boundary. For a rule action it revalidates:

1. the context and target cell;
2. the rule identity and exact conclusion;
3. the complete premise sequence;
4. the fact status of every premise;
5. one current, context-matched authoritative evidence ID per premise; and
6. the absence of forged authority fields.

It then creates a content-addressed derivation record and admits the
conclusion. A policy proposal cannot directly write `accepted_facts`.

## Invariant argument

Fix one `ContextIdentity`, finite atom universe `U`, and immutable trusted rule
set `R`. A context digest is a SHA-256 digest of canonical versioned JSON. It
is a content hash, not a CID and not itself a proof.

### Soundness relative to declared assumptions and rules

Claim: every atom in `accepted_facts` is either a declared assumption or the
conclusion of a checked derivation whose premises have supporting evidence in
the same context.

The base case is `_admit_assumption`, which constructs
`TRUSTED_ASSUMPTION` evidence only for an atom in the declared assumption
list. The inductive step is `_apply_rule_proposal`: `Rule` validation fixes
the rule and its exact ground atoms; `_validate_authoritative_evidence`
requires the exact premise sequence, current accepted premise facts, and
attached context-matched authoritative evidence; `_accept_fact` runs only
after those checks. External verification follows the same boundary with a
receipt whose context, target, verifier ID, and verifier version are checked.

Therefore policy activations and predictions cannot enter the induction. The
claim is relative to the trusted assumptions, rule records, and verifier
adapter policy; it is not a claim that those assumptions are true in the
world.

This is tested by:

- `test_ground_horn_conjunction_diamond_and_proof_carrying_trace`;
- `test_incorrect_policy_cannot_forge_a_conclusion_or_theorem_flag`;
- `test_conjunction_requires_all_premises_and_cycles_need_a_seed`; and
- `test_external_verifier_boundary_and_context_keyed_cache`.

### Monotonicity within one context

`accepted_facts` is a set and `_accept_fact` never removes an atom. Additional
valid derivations may add evidence IDs to an already accepted atom, but do not
retract the atom. A changed assumption, rule revision, candidate, dependency,
verifier, option, or axiom policy must use `new_epoch`; old evidence is kept
as `historical_evidence` and is not current evidence for the new context.

Policy/runtime version changes are separate from `ContextIdentity`, and rule
dependency fingerprints use the current premise evidence IDs rather than
operational cell ticks. An unrelated policy update therefore does not
invalidate an otherwise applicable logical proposal or evidence. The
context-change and checkpoint tests cover these boundaries.

### Finite expansion

Every accepted fact is a member of finite `U`; facts are never freshly
generated by a rule and no rule can mutate `U` or `R`. Consequently there can
be at most `|U|` first admissions in one epoch. Rule applications and
alternative evidence can be numerous, but their IDs and the event/evidence
stores are bounded by explicit limits; admission fails closed when required
authoritative evidence cannot be retained.

### Closure equivalence under fair exhaustive execution

For positive ground Horn rules, the least closure is the smallest set

```text
C = assumptions ∪ { conclusion(r) | r ∈ R and premises(r) ⊆ C }.
```

When an accepted fact is added, reverse premise indexes enqueue only rules
that depend on that fact. Messages are delivered idempotently and every ready
rule remains in the queue until serviced; non-authoritative policy actions
requeue an enabled but unproved rule. Periodic FIFO service overrides a policy
defer/reject or malformed attempt on its fairness turn and applies the
deterministic local rule action. Under the assumptions that execution is unbounded, messages are
eventually delivered, enabled rules are eventually serviced, and the rule set
does not change, every rule whose premises enter the closure is eventually
checked. No invalid rule application can add a fact. Thus the final accepted
fact set is the least closure, independent of policy priorities or fair
message interleaving, although proof choices and traces may differ.

Tests cover a starving policy, different seeded interleavings, duplicate
messages, cycles, and disconnected sparse regions. The claim does not apply
to a finite budget: `BUDGET_EXHAUSTED` is intentionally not a completeness
claim. Finite fact expansion also does not by itself prove that a buggy
scheduler terminates. This implementation's normal quiescence argument uses
queue deduplication, monotone fact notifications, and a closure check; a
policy that repeatedly defers can still consume work until fairness forces an
attempt.

## Locality, scheduling, and resources

Each rule is a rule cell with premise edges from fact cells and a conclusion
edge to the conclusion cell. Forward and reverse indexes avoid rebuilding a
knowledge graph for every local observation. The policy sees at most the
configured neighbor summary, while `mandatory_dependencies` and the checker
retain every logical premise. An explicit `REQUEST_DEPENDENCY` action is
bounded and recorded if a policy needs a dependency observation.

Initial finite graph construction, checkpoint serialization, and final report
sorting are intentionally global setup/inspection work. An ordinary fact
admission only follows the reverse premise index, sends messages to affected
rule cells, and observes that local rule neighborhood; it does not scan the
disconnected graph.

The runtime is single-process with one owner. It does not claim atomicity for
multiple processes. `ResourceLedger` reserves integer operation units before
rule work; `0` is exhausted and omitted budget is represented explicitly as
`None` (unlimited for the offline simulator). Neural activation never
replenishes that ledger; `new_epoch` carries only remaining finite units rather
than resetting the limit. Messages, proposal idempotency keys, evidence IDs,
verification cache keys, and reservations prevent duplicate delivery,
verification admission, or charging.

The external verification cache is keyed by the full external context. A cache
reuse is not a second verification event: the stored receipt, subject,
context, verifier identity/version, and typed outcome are checked before reuse.
An invalid cache entry is discarded and requires a fresh adapter call (or an
explicit unavailable outcome). Transient failures and semantic negative
outcomes are stored as distinct typed evidence; transient failures are not
cached as semantic rejection.

## Review fixes in the legacy kernel

The vertical slice also adds regressions for relevant hazards in the existing
NCA/kernel layer:

- explicit zero budget/energy is no longer converted to a nonzero default in
  the budget path;
- success/failure overlays keep per-row receipts and do not count the same
  history twice;
- journal rows have sequence IDs and replay only once;
- legacy neighborhoods use explicit board edges rather than all-skill
  insertion-order siblings;
- ARC cache admission enforces both entry and byte caps; and
- durable single-flight acquisition uses `O_EXCL` creation rather than a
  check-then-write race.

## Deliberately deferred work

The initial language does not implement variables, unification, negation,
retraction, conflicting mutable resources, synchronous vector neural rules,
distributed ownership, calibrated learned policies, or arbitrary theorem
proving. A future synchronous update layer can be added behind typed state
deltas, but it must continue to submit symbolic changes through the same
transition checker. Lean/Lake remains an optional verifier adapter rather than
being assumed by the core tests.
